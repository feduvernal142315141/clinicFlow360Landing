# 1. CONTEXTO DEL PRODUCTO

## 1.1 ¿Qué es ClinicFlow360?

ClinicFlow360 es un SaaS para clínicas, inicialmente enfocado en clínicas odontológicas.

Centraliza la operación administrativa y clínica y conecta tres actores:

1. Clínica / recepción.
2. Doctor.
3. Paciente.

La propuesta no es simplemente “tener muchas funcionalidades”, sino conectar todo el flujo de trabajo.

---

## 1.2 Plataforma web

La plataforma web incluye:

- Agenda de citas.
- Gestión de pacientes.
- Gestión de doctores.
- Expediente clínico.
- Historia clínica.
- Odontograma.
- Imágenes del paciente.
- Seguimiento de evolución.
- Recordatorios.
- Automatizaciones.
- Gestión de clínica.
- Comunicación con pacientes.

---

## 1.3 Aplicación móvil para doctores

Existe una app móvil orientada al doctor.

Incluye:

- Agenda del día.
- Citas próximas.
- Push notifications.
- Acceso a pacientes.
- Consulta del expediente.
- Captura de fotografías.
- Carga de imágenes.
- Comparación antes/después.
- Notas clínicas.
- Dictado por voz.
- Acceso rápido a información relevante.

La app debe tener fuerte presencia en la landing porque es un diferenciador visual y funcional.

---

## 1.4 WhatsApp automático

ClinicFlow360 permite automatizar comunicación con pacientes.

Ejemplos:

- Recordatorios de citas.
- Confirmaciones.
- Reagendamientos.
- Seguimiento.
- Mensajes automáticos.

No confundir estos mensajes automáticos con la recepcionista IA.

Son dos capacidades relacionadas, pero diferentes.

---

## 1.5 Recepcionista IA 24/7

ClinicFlow360 incorpora un agente de IA conectado a WhatsApp.

El agente puede:

- conversar con lenguaje natural,
- responder preguntas frecuentes,
- consultar disponibilidad real,
- agendar citas,
- cancelar citas,
- reprogramar citas,
- responder fuera del horario laboral,
- operar 24/7.

No posicionarlo como “chatbot”.

Posicionarlo como:

> **Recepcionista digital conectada a la operación real de la clínica.**

# 23. PAGOS / BILLING

La landing debe estar preparada para integrar:

- Tilopay.
- BAC Xpress Pago.
- Otro provider futuro.

No acoplar componentes directamente a Tilopay.

Crear abstracción:

```ts
interface BillingProvider {
  createCheckoutSession(input: CheckoutInput): Promise<CheckoutSession>;
  cancelSubscription(id: string): Promise<void>;
  reactivateSubscription(id: string): Promise<void>;
  getSubscription(id: string): Promise<Subscription>;
}
```

Flujo:

```text
Landing
  ↓
Elegir plan
  ↓
Backend
  ↓
Payment Provider
  ↓
Hosted Checkout
  ↓
Webhook
  ↓
Subscription ACTIVE
  ↓
Crear / activar clínica
```

Nunca almacenar:

- card number,
- CVV,
- datos sensibles de tarjeta.
